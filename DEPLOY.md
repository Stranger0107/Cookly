# Deploying Cookly

Cookly deploys as **one web service on Render**: Express serves the API at `/api/*` and the
built React app for every other URL. Data lives in a free **MongoDB Atlas** cluster.

```
 browser ──► https://cookly-xxxx.onrender.com
                 │
                 ├── /api/*   Express API ──► MongoDB Atlas
                 │                       └─► TheMealDB
                 └── /*       React app (cookly-frontend/dist)
```

Everything is configured in [`render.yaml`](render.yaml). You only need two free accounts.
Total time is about 10 minutes.

---

## 1. Create the database (MongoDB Atlas)

1. Sign up at <https://www.mongodb.com/cloud/atlas/register>.
2. **Create a cluster:** choose **M0 (Free)**, provider **AWS**, region **Mumbai (ap-south-1)**
   or **Singapore** (close to the Render region in `render.yaml`).
3. **Database Access → Add New Database User:** pick a username and click
   *Autogenerate Secure Password*. Copy the password somewhere safe.
4. **Network Access → Add IP Address → Allow access from anywhere** (`0.0.0.0/0`).
   Render's free tier has no fixed outbound IP, so this is required. Access is still
   protected by the database username and password.
5. **Database → Connect → Drivers:** copy the connection string. It looks like
   `mongodb+srv://<user>:<password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority`
6. Put your password in it, and add the database name `cookly` after `.net/`:

   ```
   mongodb+srv://cookly_app:YOUR_PASSWORD@cluster0.abcde.mongodb.net/cookly?retryWrites=true&w=majority
   ```

   If the password contains `@ : / ? # %`, URL-encode those characters (e.g. `@` → `%40`).

## 2. Deploy the app (Render)

1. Sign up at <https://dashboard.render.com/register> with your **GitHub** account.
2. Open <https://dashboard.render.com/blueprints> → **New Blueprint Instance**, connect
   GitHub if asked, and pick the **Stranger0107/Cookly** repository.
   (Or use the one-click link: <https://render.com/deploy?repo=https://github.com/Stranger0107/Cookly>)
3. Render reads `render.yaml` and asks for the one secret it can't generate:
   **`MONGO_URI`**. Paste the connection string from step 1.6.
4. Click **Apply**. The first build takes about 3–5 minutes.
5. When it shows **Live**, open the URL (e.g. `https://cookly-xxxx.onrender.com`) and check
   `https://cookly-xxxx.onrender.com/api/health`. It should say `"database":"connected"`.

`JWT_SECRET` is generated by Render automatically. Every push to `main` redeploys.

## What render.yaml sets up

| Setting          | Value |
|------------------|-------|
| Build            | backend `npm ci --omit=dev`, frontend `npm ci` + `npm run build` |
| Start            | `npm --prefix cookly-backend start` |
| Health check     | `/api/health` (Render restarts the app if it fails) |
| `NODE_ENV`       | `production` (stricter rate limits, trust proxy, no stack traces) |
| `JWT_SECRET`     | generated by Render |
| `MONGO_URI`      | **you paste it** |

## Good to know

- **Free tier sleeps** after 15 minutes without traffic. The first visit after that takes
  ~30–60 seconds to wake up. A paid instance ($7/month) stays awake.
- **Logs:** Render dashboard → *cookly* → *Logs*. Startup errors like a wrong `MONGO_URI`
  show up there ("Failed to start server: ...").
- **Custom domain:** Render → *Settings* → *Custom Domains*.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Deploy fails with `Missing required environment variables: MONGO_URI` | Add `MONGO_URI` under *Environment* and redeploy. |
| Logs show `bad auth : authentication failed` | Wrong Atlas username/password in `MONGO_URI` (check URL-encoding). |
| Logs show `Server selection timed out` | Atlas *Network Access* is missing `0.0.0.0/0`. |
| `/api/health` returns 503 | The app started but lost the DB connection; check Atlas is running. |

## Alternative: frontend and API on separate hosts

If you'd rather host the React app on Vercel/Netlify and the API elsewhere:

1. Frontend: build with `VITE_API_URL=https://your-api.example.com/api` and add a rewrite
   of all paths to `/index.html` (for React Router).
2. API: set `CLIENT_URL=https://your-frontend.example.com` so CORS allows it.
